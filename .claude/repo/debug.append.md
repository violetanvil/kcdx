## Repo additions — debug

- **Crash / failure triage tooling (§B.1 ground truth)** — read a crash dump with the cdb one-liner: `"C:/Program Files (x86)/Windows Kits/10/Debuggers/x64/cdb.exe" -z <dump> -c "<commands>"` (e.g. `.ecxr; !analyze -v; k 30; q` for the faulting stack; `~* k 25; q` for all threads; `lm; q` for modules) — read `EXCEPTION_CODE_STR` + `FAILURE_BUCKET_ID`. Dump locations: watchdog crash zips at `<game-bin>/kcdx-engine/logs/crash/crash_<ts>.zip`; BugSplat dumps at `%LOCALAPPDATA%/CrashDumps/` (SEH-trappable) or NTFS alternate data streams in `%TEMP%` (AV crashes — dumps may not reach disk). Log tail: last 30 lines of `kcdx-engine/logs/kcdx_<ts>.log` + `kcdx-dev_<ts>.log` from the failing session, grepped on the structured-KV category tag. Do NOT enable Application Verifier page heap without strong reason — its perturbation produces different unrelated crashes (emergency-only).

- **Build + deploy of a probe (§B.3)** — the agent writes the probe, runs `pwsh ./build.ps1`, deploys the diff-scoped artifact + hash-verifies (`Get-FileHash`) + enables dev mode per `.claude/rules/agent-builds-and-deploys.md` (the deploy mapping + hash recipe are the orchestrator-loop's §C.6 — do not duplicate); the user runs ONLY the launch. After the run the agent reads `kcdx-dev_<ts>.log` directly. Asking "should I write / build / deploy the probe?" is a flow defect — none are decisions.

- **Probe-instrumentation form** — an in-source probe is marked `// === DIAGNOSTIC (PROBE X)` and logs via `LOG_DEBUG_KV("CATEGORY", "action", log::KV("k", v), ...)` under a stable category tag (`MID_HOOK`, `SCRIPTING`, …) so the dev log greps reliably; freeform printf does not. **No-residue model (per `.claude/rules/working-artifacts.md` + `.claude/rules/results-driven.md`):** when a probe's question is answered, capture the finding + the probe's reusable wiring (its instrumentation recipe / script) into the artifact tree, THEN remove the probe from source — live source returns to pure production logic with ZERO residue (no dormant branch, no `#if 0` block, no commented-out corpse, no runtime-disabled flag). The next investigation reconstructs the probe from the artifact tree, never from source. This supersedes the §E "archive in place" convention. The worked C++ skeletons live at `docs/re-reference/probe-patterns.md` — point at it; do NOT inline them.

- **Probe methodology — six shapes** (full skeletons at `docs/re-reference/probe-patterns.md`): (1) **read-only observation** — dump the raw state at a point, no side effects, lowest cost; (2) **bypass a subsystem** — comment one call site, state the negative consequence in the log line, bypass one thing at a time; (3) **fingerprint / canary** — FNV-1a hash a block at N checkpoints to detect clobbering between time A and B; (4) **time-bisect via worktree** — `git worktree add -d` a known-good commit, build + deploy + reproduce to settle "regression or older?"; (5) **ABI / pointer-identity** — record every distinct handle/state/pointer through a site to confirm you captured the canonical one; (6) **reverse-order** — run `B; A` when `A; B` corrupts and B is the suspect, to learn whether the bug is intrinsic to B or A primed it. **Picking the next probe** (prefer cheapest-most-falsifying first): read-only → bypass → fingerprint → time-bisect → reverse-order. Each probe has ONE question; "add 10 log lines and see" is a search, not a probe.

- **KI-doc probe-Trail discipline** — the KI Trail is a strict table; each probe is one row:
  - **Action cell:** `PROBE <letter>[.N]: <≤15 words: the one variable changed>` — no hypothesis, no prediction. Add the row with a `pending` Result BEFORE the launch; update it immediately AFTER (one-pass authoring — never speculative, never rewrite an earlier Result when a later probe reframes it; add a new Fact citing both).
  - **Result cell:** `<outcome verdict>. <one clause interpretation>.` — two sentences max, 200-char hard cap; the clause names which hypothesis the result eliminated or supported, nothing else.
  - A multi-change launch decomposes into sub-rows sharing the launch letter (`K.1`, `K.2`, …), one variable per row.
  - **Facts** are empirical only (each bullet ends `(PROBE <letter>)`); causal claims live ONLY in **Open questions**, labeled, never in Facts.
  - Hypotheses, predictions, methodology details, reframes, and multi-paragraph analysis each have a named destination OTHER than the Trail row (Open questions / Active diagnostic instrumentation table / a `## Reframe` or `## Analysis` section).
  - **Frontmatter:** `id: KI-NNNN` / `opened: YYYY-MM-DD` / `status: open` / `commit_at_filing: <40-char hash>`. KI-NNNN allocation scans `docs/known-issues/` AND `docs/known-issues/closed/` for the highest id + 1; the pre-KI human-readable `<title>.md` files carry NO id and are NOT part of the allocation sequence.

- **Design-surface threshold (Gate A / Gate B)** — a planned fix crosses the boundary (Gate A architect-review fires; Gate B verifier's §4 design-fork check fires) when it: adds or changes a hook surface / ABI signature / vtable slot / Address Library entry / save-cosave field / `[[...]]` schema; OR adds a new `src/` or `include/` file; OR modifies >1 `src/` file; OR changes a function signature (grep every caller first); OR touches a `.claude/rules/` file or `docs/design.md`. A trivial fix (a log-message typo, a comment, a single-file ≤10-line change with no signature/rule touch) skips both gates.

- **Cornerstone gate (Gate A design forks)** — every surfaced option set clears `.claude/rules/cornerstones.md` §"Surfaced options clear the cornerstones first" BEFORE presenting.

- **Provisional-mask policy** — the AP17 escape: a user-approved "Provisional mask, root cause unknown" Resolution label is permitted; the KI then stays OPEN and top-level (it does NOT graduate to `closed/`). Absent that explicit label, no close lands without a root-cause MECHANISM paragraph.
