--------------------------------------------------------------------------------
4. WHICH kcdx DEVIATION FLIPS IT (apex answer)
--------------------------------------------------------------------------------
The gate reads the engine's LEVEL-NAME / current-level RECORD chain
(Game->[0x88]->[0x58], name @[+0xc8]). The CET task fails (raises 0xD2) when that
record / its name is not validly populated by the time CET_PrepareLevel runs.

Populating that record requires the level's own metadata to load — exactly the
files kcdx is observed to MISS in the failing full-swap run (ROOT-CAUSE-
existence-overreport.md): levels/kutnohorsko/auto_resourcelist.txt +
resourcelist.txt resolve to result=0/how=miss-original. If the level's
resourcelist/level-record read fails, the current-level record never populates ->
CET_PrepareLevel's name/record gate is empty -> 0xD2 abort -> MessageBox.

UNVERIFIED (honestly marked — needs a live probe, NOT static inference):
  - The EXACT producer call that writes Game->[0x88]->[0x58] / [+0xc8] from a file
    read is one+ frames ABOVE this CET task (the level-mount/level-info loader);
    its body was not traced this front (out of the apex's minimal scope).
  - WHETHER the empty-record path (gate je) or the string-length-0 path is the one
    the full-swap boot actually takes is not distinguishable from the dump alone
    (both reach the same epilogue); the dump confirms ONLY that execution is in the
    MessageBoxA under this CET, which is the 0xD2 path.
  - flagA 0x18492ba38 / flagB 0x18492bbd1 writers not traced (they gate whether the
    failure reports vs silently returns; not the load test itself).
